    Can it be glass or blur?

    No, not natively. Google Wallet has no glass or blur material. The background is one solid color, there are no gradients, and text never sits on top of an image. The closest look is to bake the blur into the hero image: blur and fade its edges into the background color, as in “Baked glass edges”. It looks soft, but it’s part of the picture, so it doesn’t react to anything.

    Google's "featured action": examples

    Google has no feature literally called "featured actions". There are two real things:

    1. App link button (appLinkData): exactly 1 per pass, label ≤ 30 chars, no icon (Google marks the logo, title and description as not supported). If an Android app is set it opens the app, otherwise the web link. That's what Badge's "1 Featured Action, ~30 chars, Android package wins" describes: it's Badge's name for this button. Ours is "Open Auto Club app".

    2. Value-added modules (valueAddedModuleData): the ones with your own text and image. If the pass has exactly one, it shows on the front under the hero image. Add more and they all move to a list in the details (up to 15). These screenshots are from Google's docs:

    uri (required) is where a tap goes: a web link or a deep link (our Roadside one is an App Link that opens the app’s chatbot; the phone number stays in the links list). sortIndex picks which comes first (lower wins), so with one slot on the front, it decides what members see. viewConstraints.displayInterval sets start/end dates, handy for "Renew now" only near expiry. Modules can live on the class (everyone) or the object (one member).

    Use the switch above the card to see both setups with our AAA modules.

    Featured actions: Apple vs Google

    Google Wallet doesn't have Apple's fixed “Featured Actions”. The closest things are value-added modules (custom tappable cards), the app link button, and the links module in the details. Unlike Apple, you write the text and pick the image yourself.

    Apple Wallet (iOS 27)Google Wallet

    "valueAddedModuleData": [{
  "header": {"defaultValue": {"language": "en-US", "value": "Roadside Assistance"}},
  "body":   {"defaultValue": {"language": "en-US", "value": "Get help in the app: tow, battery, tire, lockout"}},
  "image":  {"sourceUri": {"uri": "https://…/vam-roadside.jpg"}},
  "uri": "https://www.ace.aaa.com/wallet/roadside?source=google-wallet",
  "sortIndex": 1,
  "viewConstraints": {"displayInterval": {"end": {"date": "2027-03-31T23:59:00-07:00"}}}
}]
    How to add the app link button (JSON) 
    "appLinkData": {
  "androidAppLinkInfo": {"appTarget": {"targetUri": {"uri": "https://play.google.com/…", "description": "AAA app"}}},
  "webAppLinkInfo":     {"appTarget": {"targetUri": {"uri": "https://www.ace.aaa.com/", "description": "Website"}}},
  "displayText": {"defaultValue": {"language": "en-US", "value": "Open Auto Club app"}}
}

    Google marks the per-link title, description and appLogoImage as not supported, and iOS app links aren't supported either.

    How the pass is laid out (2026 redesign)

    Google moved passes to a full-screen look: no more card on a grey background. Your hexBackgroundColor fills the whole screen, so contrast matters more now (Google still picks white or black text for you).

    Top to bottom: round logo in the middle, cardTitle under it, then the header big and bold (up to two lines). Then the barcode with its alt text, then the field rows from cardTemplateOverride (1, 2 or 3 per row). The hero image becomes a full-width band, the biggest visual on the pass, so it's worth a good picture.

    Scroll down and links, the app link button and modules show as tinted, tappable rows with icons. Pass settings (notifications, archive, remove) has its own screen now: tap it in the mock.

    Source: WalletWallet: Google Wallet passes redesign 2026. Google hasn't published how value-added modules look in the new design, so that part is my best guess. The JSON fields and limits didn't change.
