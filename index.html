  • Logo top-left, ≈26 pt tall

3Header darkening

  • Default: dark gradient behind the header
  • Apple gives no %
  • suppressHeaderDarkening: true turns it off

4Barcode

  • 77% of the card width, centered
  • ≈260–351 pt
  • Sits in front of the footer, never blurred
  • Overlaps the footer by ≈10 pt = 11% of the barcode
  • No barcode: the art shows there, nothing moves

5Footer area

  • Starts at ≈341 pt (76% down)
  • Primary fields + 1 footer line
  • Footer labels are hidden

6Footer color set

  • footerBackgroundColor: solid band, art hidden
  • Fade the art into the same color

7No footer color = glass

  • Blur ≈11% of the card width
  • Saturation 145% · brightness 94%
  • Apple gives no %; ours matches Pass Designer
  • Light glass needs light art: add a white veil (57% / 39% in our AA cards)

8Fonts

  • Can’t be changed: a pass has no font setting
  • Wallet always uses Apple’s system fonts
  • Labels and values are monospaced
  • Brand font (Roboto) only baked into the art

9Text colors

  • foregroundColor = values · labelColor = labels
  • Solid rgb() only
  • Aim for 4.5:1

10Automatic colors

  • useAutomaticColors: true: Wallet picks the text colors and ignores yours

11Featured Actions

  • Up to 2 cards below the pass
  • Pick from Apple’s 14 predefined actions
  • Icon and title are set by Apple
  • e.g. membershipBenefits, place

Text contrast · ADA (WCAG 2.2 AA)

Each card’s iOS 27 text checked against what sits behind it: the frosted glass footer, the solid footer, or the photo under the header. AA needs 4.5:1 for regular text. None of the Wallet poster text is large enough for the 3:1 large-text rule. Pick a card to see every line.

  • How it’s measured: the glass is rebuilt from each template’s artwork the same way the viewer draws it (blur 34px, saturate 1.45, brightness .94), which matches Pass Designer to within about 10–20 RGB levels. Every pixel behind each line of text is checked, and “Lowest” is the worst spot.
  • Glass drift: the lowest ratio again after shifting the glass 15 RGB levels toward the text color (less contrast), to cover the difference from Pass Designer and the device. A card only counts as safe when this column passes too.
  • Original cards use automatic colors, so Wallet picks the text color from the art. The viewer approximates that pick, and the white and dark columns show both possible outcomes.
  • Not covered: iOS 26 cards (solid colors, no glass), the barcode panel (black on white), and Apple Watch. Confirm on a device with Xcode’s Accessibility Inspector before shipping.

“Get Directions”: how the branch (Maps place ID) gets set and updated
What's in the pass{"type": "place", "identifier": "nearestBranch", "placeIdentifier": "I71B28B9C6AC9C7EF"}. placeIdentifier is an Apple Maps Place ID (the sample is one AAA branch). identifier is just our own name for the action. It pairs with the back field that has the same key (“Your AAA branch”) and never needs to change. How we'd push a new locationThe pass can't be edited in place, so we send a new version of it. (1) When we first build the pass, include webServiceURL (our pass service) and an authenticationToken. (2) When the member adds it, Wallet registers the device with our service and gives us a push token. (3) When the branch changes (member moved, branch closed, better match), the server saves the new place ID and sends an empty push through APNs with our Pass Type ID certificate. (4) Wallet wakes up, asks our service which passes changed, and downloads the newly signed pass with the new placeIdentifier (and new locations for Lock Screen suggestions). The member doesn't do anything; Get Directions just points to the new branch. Optional: a changeMessage on the “Your AAA branch” back field shows a notification like “Your AAA branch is now %@”. Does it need our server?Yes. Whatever builds and signs the member's .pkpass (with our Pass Type ID certificate) writes the place ID in when it generates the pass. Updating it later needs the Wallet web service on our side: webServiceURL + authenticationToken in the pass, devices register, we send an APNs push, and Wallet downloads the new signed pass. One for everyone, or per member?Per member. Each pass gets one place: the member's home branch, or the branch nearest the address on file. Everyone getting the same branch only makes sense for a demo. Can it follow the phone's location?Not live. Wallet doesn't pick a “nearest branch” when you tap; the action always opens the place that's in the pass. Options: (1) update it when the member moves or changes their branch, using a push update; (2) also add up to 10 nearby branches to locations with relevantText so the pass shows up on the Lock Screen near them. That's for relevance only and doesn't change the button. Where do place IDs come from?Look them up on the server with the Apple Maps Server API (search for the branch and get its place ID) or MapKit (MKLocalSearch, then check it with MKMapItemRequest). That's how i found the sample one. Store it with each branch record so we don't search for every pass. Keep them validPlace IDs are meant to stay stable, but places can merge or move, and Wallet drops the action if the ID doesn't resolve. Re-check stored IDs every so often (Apple can give back a newer ID for an old one) and regenerate affected passes.

  2. Pass generation: fill placeIdentifier from the member's branch; also fill the matching “Your AAA branch” back field (name, address, phone).
  3. Set up the Wallet web service (register, list updated passes, return the latest pass) and push updates when a member's branch changes.

“View Membership Benefits”: what tapping it does
What it isOne of Apple's Featured Action types (membershipBenefits). Apple sets the label and icon; we only give it an https link. A pass can have 2 actions, and iOS 26 and older don't show them at all. The plan (agreed)Tapping opens the Auto Club app on the Membership Benefits bottom sheet (same style as the Discounts filter and sort sheets, glass close button) with Roadside Assistance first, so the button's label matches what members see. Without the app, the same link opens the membership page on ace.aaa.com. Today, in this proposalThe link is https://autoclubapp.page.link/wallet-benefits. It only opens the app, on whatever screen was last open, because the app still claims that old Firebase Dynamic Links domain. Google shut that service down, so it can stop working any time, and without the app it shows “not found”. iOS 26 and olderNo Featured Actions there, so the cards show the Roadside number (1-800-400-4222) on the front instead, and the back of the pass keeps tappable phone numbers and links. Can't changeThe label (“View Membership Benefits”), the icon, the 2-action limit, and that front fields aren't tappable.

What we need

  1. Web / platform: host an apple-app-site-association file on an AAA domain (for example www.ace.aaa.com) that claims one path, such as /wallet/benefits, and serve the membership page at that same URL for people without the app.
  2. iOS: add applinks: for that domain and a deep-link route that opens the Membership Benefits sheet with Roadside first. The app's deep links today only cover push notifications (My Cards, Pay Bill), so this is a new route.
  3. Design: finalize the sheet (it's marked “proposal, not final” in the images above): content, order and the Roadside call-to-action.
  4. Backend (pass service): put the new link in the pass's Featured Action when it builds the card. Add something like ?source=wallet so analytics can count opens from Wallet.
Lock Screen suggestions near AAA places (like a gym key)
How others do itA gym key that pops up on the Lock Screen near the gym is a Wallet pass feature, not the gym's app. The pass lists up to 10 locations (latitude/longitude, an optional short message like “Your AAA card is ready”, and maxDistance, which can only make the radius smaller). The iPhone checks them in the background and suggests the pass when you're close. It doesn't need the app installed or location permission, and the company never sees where the member is. Passes can also wake up from a Bluetooth beacon (good indoors) or at a date and time (relevantDates). Where we areThe app already downloads the Membership card from our backend (PostMembershipPKPass, pass type pass.com.aaa.membercard, sending the member's ZIP code) and adds it to Wallet; Insurance works the same way. The server builds and signs the pass, so this needs no app change. It's backend work. What we can doAdd the member's 10 nearest AAA places to the pass, picked from their ZIP code: branches, approved repair shops, or the most-used discount partners. Add a short message per place, plus dates where useful (renewal, policy start). The same works for the Insurance card. Keep it currentWith the Wallet web service (push updates), the server can refresh the list later (new branch, member moved) without the member adding the card again. The app only needs to re-add the card when the member changes ZIP or club. Limits10 places per pass, so it's “nearest 10”, not every partner. Apple decides when the pass actually appears; we can't force it. The message is short, fixed in the pass and the same for every visit. Test on a real device: whether iOS 27 suggests poster passes this way is Apple's call.

What we need

  1. Product: pick the place types (branches, repair shops, discount partners) and the Lock Screen message for each.
  2. Backend (pass service): add locations (nearest 10 to the member's ZIP), relevantText and, if wanted, relevantDates and beacons when generating the pass; then the Wallet web service for updates.
  3. iOS: nothing to start. Later, re-add the card when ZIP or club changes.
